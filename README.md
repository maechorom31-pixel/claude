# gichul — 기출 시험지 PDF 문항 검색기

모의고사·수능 PDF를 쌓아 두면, **단어를 검색해서 "2026학년도 고3 7월 학평 ·
생명과학I · 14번" 처럼 출처와 함께** 찾아 주는 도구. 문항을 누르면 원본 PDF에서
그 문항만 오려 그림·표까지 그대로 보여준다.

윤문(문항 다듬기)에서 "이 표현을 예전에 어떻게 썼더라"를 매번 PDF를 열어
찾던 일을 없애려고 만들었다.

```
$ gichul search 빛에너지
'빛에너지' — 4개 문항 / 4회 등장

표기 분포 (띄어쓰기·부호 차이):
     2회  '빛에너지'
     2회  '빛 에너지'

■ 2014학년도 수능 · 생명과학I · 1번   [p.1 · 2014_수능_생명과학1.pdf]
   … ④ 소나무는 《빛에너지》를 흡수하여 양분을 합성한다. ⑤ 사막여우는 …
```

## 왜 PDF 리더기의 Ctrl+F 로는 안 되나

폴더 전체 검색은 Acrobat 이나 PDF-XChange 에도 있다. 다른 점은 넷이다.

| | PDF 리더기 | gichul |
|---|---|---|
| 띄어쓰기 | `빛에너지`로 찾으면 `빛 에너지`를 놓친다 | 둘 다 걸린다 |
| 출처 | "파일명 3쪽" | "2014학년도 수능 · 생명과학I · **1번**" |
| 표기 통계 | 없음 | `빛에너지` 2회 / `빛 에너지` 2회 — 어느 쪽이 관례인지 바로 보인다 |
| 과목 | 폴더로 나눠 둬야 한다 | 표지에서 자동 인식, 드롭다운으로 선택 |

띄어쓰기와 출처가 핵심이다. 윤문할 때 필요한 건 "이 낱말이 있나"가 아니라
"**전례가 어떻게 썼나, 어디에 있나**"이기 때문이다.

## 설치

```bash
pip install pymupdf          # 유일한 의존성. 나머지는 파이썬 표준 라이브러리
```

## 쓰는 법

### 쌓기

```bash
python3 -m gichul ingest ./모의고사            # 폴더째로. 이미 넣은 파일은 건너뜀
python3 -m gichul watch  ./받은자료            # 폴더 감시. 새 PDF가 생기면 자동 색인
```

출처는 표지·머리글에서 자동으로 읽는다. 못 읽으면 파일명에서 찾고
(`2026_6월모평_생명과학1.pdf`), 그것도 안 되면 직접 지정한다.

```bash
python3 -m gichul ingest a.pdf --year 2026 --exam "6월 모평" --subject 생명과학1
```

### 찾기

```bash
python3 -m gichul search 상리공생                    # 띄어쓰기 무시
python3 -m gichul search 마그마 --subject 지구과학1   # 과목 한정
python3 -m gichul variants "옳은것만을"              # 표기·띄어쓰기 용례 통계
python3 -m gichul compare "옳은 것만을" "적절한 것은"  # 표현 빈도 비교 (어순·어투 결정)
python3 -m gichul show 76 --png q.png                # 문항 하나를 텍스트·표·이미지로
```

`--subject` 는 `생명과학1`, `생명과학I`, `생명과학Ⅰ` 를 모두 같게 본다.

### 브라우저에서

```bash
python3 -m gichul web        # http://127.0.0.1:8765
```

과목 선택 → 검색 → 결과 클릭 → 그 문항의 실제 지면. PDF 업로드도 이 화면에서
하면 바로 색인에 쌓인다.

### 파일 하나로 묶어 보여주기

```bash
python3 -m gichul html 기출검색.html                  # 전체
python3 -m gichul html 국어.html --subject 국어        # 과목만
python3 -m gichul html 수능.html --exam 수능 --year 2025
```

문항 텍스트와 지면 이미지를 안에 넣은 HTML 한 개를 만든다. 검색이 브라우저에서
돌아가므로 파이썬도 서버도 필요 없다. 다른 사람에게 보내거나 보관할 때 쓴다.

지면 이미지는 문항당 30–90 KiB 라, 문항이 많으면 자동으로 빼고 텍스트만 담는다
(기준은 `--max-mb`, 기본 12MB). 강제하려면 `--images`, 아예 빼려면 `--no-images`.
문항이 수천 개가 되면 **과목별로 갈라 뽑는 쪽이 현실적이다.**

## 과목을 늘려 갈 때

국어·영어·수학·사탐·과탐을 계속 쌓는 것을 전제로 만들었다.

- **과목은 표지에서 자동으로 갈린다.** 국어 영역의 선택과목(화법과작문·언어와매체
  ·독서·문학), 사탐 9과목, 과탐 8과목, 통합사회·통합과학까지 인식한다.
- **옛 수학 가/나형·A/B형은 다른 과목으로 잡는다.** `수학 영역 (가형)` 은 괄호 안이
  과목이 아니라 시험지 유형인데, 가형과 나형은 문항이 다르므로 `수학가형`,
  `수학나형` 으로 갈라야 용례가 섞이지 않는다.
- **국어·영어 지문은 문항과 따로 잡는다.** `[1~3] 다음 글을 읽고…` 를 지문
  세그먼트로 보관하고 `1~3번 지문` 으로 출처를 적는다. 지문에서만 쓰인 표현도
  검색된다.
- **과목별로 좁혀 쓰는 게 낫다.** 용례는 과목마다 관례가 다르다.
  `--subject 국어` 로 좁히면 국어 안에서의 우세 표기가 보인다.

```bash
python3 -m gichul subjects       # 과목별로 몇 개 쌓였는지
python3 -m gichul stats          # 시험지 하나하나
```

`subjects` 에 `(미상)` 이 보이면 그 시험지는 과목을 못 읽은 것이다.
`ingest --subject` 로 지정해 다시 넣으면 된다.

### 계속 쌓는 흐름 — 세 가지 방법

**① GitHub 에 올리기만 하면 끝 (추천 · 설치 불필요)**

이 저장소의 `pdfs/` 폴더에 PDF를 올리면 (GitHub 웹 → Add file → Upload files)
1~2분 뒤 자동으로 색인되고 검색 페이지가 다시 만들어진다.

```
pdfs/에 PDF 업로드
   → 자동 파싱 → data/archive.jsonl.gz 에 누적  (진짜 데이터, MB 단위)
   → data/REPORT.md 에 처리 결과              (확인할 것은 이것뿐)
   → site/ 검색 페이지 재생성                  (Pages 주소 또는 Actions 결과물)
```

- 같은 파일을 두 번 올려도 내용으로 알아보고 건너뛴다.
- 과목을 못 읽으면 REPORT 에 뜬다. **파일명에 과목을 넣어 이름만 바꾸면**
  다음 실행에서 채워진다 (내용으로 대조하므로 개명해도 안전).
- 용량이 차면 오래된 PDF를 지워도 된다. 텍스트·검색·용례는 JSONL 에 남고,
  그 시험지의 지면 이미지만 빠진다.
- 검색 페이지를 주소로 쓰려면 한 번만: Settings → Pages → Source 를
  "GitHub Actions" 로. (비공개 저장소는 유료 요금제에서만 Pages 가 된다 —
  안 되면 Actions 실행 결과물(Artifacts)에서 zip 으로 받는다.)

**② 내 컴퓨터에서 더블클릭** — `시작.bat`(Windows) / `시작.command`(macOS).
브라우저가 열리고, 화면에서 PDF를 업로드하면 바로 쌓인다. Python 설치 한 번만
필요하다.

**③ 명령줄** — `ingest`/`watch`/`export`. 위에서 설명한 대로.

JSONL 과 HTML 은 산출물이지 중간 단계가 아니다. 어느 방법이든 PDF를 넣는
순간 검색이 된다.

## 용량

색인은 **추출된 텍스트만** 담는다. 원본 PDF는 제자리에 두고 경로만 참조한다.

| 규모 | 원본 PDF | 색인 DB | JSONL(gzip) |
|---|---|---|---|
| 탐구 시험지 500개 (문항 20개) | 약 1–2 GB | **21 MiB** | 약 5 MiB |
| 국어급 시험지 500개 (문항 45개) | 약 2–4 GB | **72 MiB** | 약 15 MiB |

10년치 전 과목을 쌓아도 색인은 100 MiB 안쪽이다. 검색은 25–70 ms.

```bash
python3 -m gichul export backup.jsonl.gz    # 데이터 파일로 내보내기
python3 -m gichul import backup.jsonl.gz    # PDF 없이 색인 복원
python3 -m gichul compact                   # DB 조각 정리
```

원본 PDF를 지워도 검색·텍스트·표는 그대로 쓸 수 있다. 다만 **문항 이미지는
원본 PDF가 있어야** 만들어진다.

## 한계

실제 2026학년도 7월 학평 과탐 4과목으로 검증한 결과.

- **수식은 텍스트로 안 나온다.** 시험지는 수식·첨자를 전용 글꼴로 찍는데
  유니코드 매핑이 없어 글자를 복원할 수 없다. 화학I 10.7%, 물리학I 4.9%가
  이런 문자였다. 추출 텍스트에서는 `□` 로 표시하고, 색인할 때 비율을 알려 준다.
  → **수식이 든 문항은 이미지 보기로 확인해야 한다.** 국어·사탐·생명과학처럼
  산문 위주 과목은 거의 영향이 없다 (생명과학I 0.5%, 지구과학I 0.2%).
- **줄바꿈에 걸친 띄어쓰기는 판정하지 않는다.** 한국어 조판은 낱말 가운데서도
  줄을 바꾸므로 `옳은 것만`+개행+`을` 이 원래 붙여 쓴 건지 알 수 없다. 세면
  없는 사례가 생기므로 "판정 불가"로 따로 센다.
- **표는 구조가 부분적으로만 살아난다.** 셀 구획은 잡히지만 수식이 든 칸은
  비어 나온다. 원본 이미지가 정답이다.
- **스캔본은 OCR이 필요하다.** 텍스트가 거의 없는 페이지는 색인할 때 경고한다.
  (OCR 기능은 아직 없다.)
- 문항 분할은 `14.` 같은 줄머리 번호를 순번이 맞을 때만 인정한다. 편집 형식이
  아주 다른 시험지는 번호가 빠질 수 있고, 그때도 경고를 띄운다.

## 구조

```
gichul/
  normalize.py   표기 정규화 — 띄어쓰기 무시 검색의 핵심, 원문 위치 매핑
  extract.py     PDF -> 읽기 순서 텍스트 (2단 편집 처리, 좌표·표 수집)
  segment.py     텍스트 -> 문항 단위 (+ 문항이 놓인 지면 좌표)
  meta.py        표지·머리글·파일명 -> 학년도/시험/과목
  index.py       SQLite FTS5(trigram) 저장·검색·용례 집계
  render.py      문항 영역을 PDF에서 오려 PNG 로
  pipeline.py    PDF 한 개를 색인에 넣기까지
  archive.py     JSONL 데이터 파일 내보내기·불러오기
  watch.py       폴더 감시 자동 색인
  web.py         표준 라이브러리만 쓰는 웹 UI
  standalone.py  색인을 자립형 HTML 한 개로 (검색까지 브라우저에서)
  cli.py         명령줄
```

설계에서 중요한 두 가지.

1. **검색 키는 저장하지 않는다.** 공백을 지운 검색 키는 본문과 크기가 비슷해서
   같이 저장하면 DB가 두 배가 된다. SQLite 가상 생성 열로 즉석 계산한다
   (47 MiB → 21 MiB). 이 SQL 식은 `normalize.py` 의 표를 읽어 만들기 때문에
   파이썬 쪽과 어긋날 수 없고, 테스트로도 고정해 두었다.
2. **한국어는 trigram 토크나이저로 찾는다.** 공백 단위 토큰화는 조사 때문에
   잘 안 맞는다. trigram 은 부분 문자열 검색이라 `에너지를`, `에너지가` 가
   모두 걸린다. 3글자 미만 검색어는 색인을 못 쓰므로 값싼 초벌 거르기 후
   정확한 판정만 파이썬에서 한다.
